# `pkg/parser/generate.rs`

## 文件定位

[`generate.rs`](./generate.rs) 属于 `astersql-parser` crate。crate 根 [`lib.rs`](./lib.rs) 以 `pub mod generate { include!("generate.rs"); }` 装入本文件，因此唯一符号可通过 `astersql_parser::generate::GENERATED_RUST_TABLES` 访问；它没有被再导出到 crate 根。

本文件是解析器生成流程的兼容与发现入口，只声明已提交到仓库的三份 Rust 解析表路径。它不是生成器实现，也不在普通构建时执行生成。真正的显式生成与防漂移检查位于 `pkg/parser/parsergen` 的独立 `astersql-parsergen` crate；运行时解析器则由 [`lib.rs`](./lib.rs) 直接 `include!` 三份已提交产物。

## 核心职责

- `GENERATED_RUST_TABLES` 集中列出 `generated/main_tables.rs`、`generated/hint_tables.rs` 和 `generated/lexer_tokens.rs` 三个相对路径。
- 文件级说明记录维护契约：`astersql-parsergen generate` 从 `.astergram` 文法显式生成产物，普通 parser 构建只消费已提交文件。
- 该清单提供稳定、只读的公开元数据，便于工具或后续检查统一发现生成产物；当前仓库搜索没有发现目标常量的直接调用者，因此不能把它描述为现有生成命令或构建流程的驱动数据。

## 主要符号

- `pub const GENERATED_RUST_TABLES: &[&str]`：静态字符串切片，依次包含主解析表、Hint 解析表和 lexer token 表的仓库相对路径。切片及其元素均为 `'static` 数据，没有运行时初始化或所有权转移。

本文件没有类型、trait、函数、`impl`、可变静态量或条件编译项。公开 API 只有上述常量；模块是否公开由 [`lib.rs`](./lib.rs) 决定。

## 执行流程

本文件自身没有可执行流程。其静态关系分为两条彼此独立的链：

1. 维护者显式运行 `astersql-parsergen generate`；`parsergen/main.rs::main` 定位 `pkg/parser`，调用 `write_generated_outputs`。
2. `parsergen/generate.rs::generate_outputs` 读取 `grammar/main.astergram` 与 `grammar/hint.astergram`，构造解析表并形成三个命名输出；`write_generated_outputs` 将它们写入 `generated/`。`check_generated_outputs` 只比较当前内容，发现缺失或陈旧时返回错误，不改文件。
3. 普通 `astersql-parser` 编译不调用上述生成器。`parser_impl` 直接包含 `generated/main_tables.rs`，内部 `lexer_support` 直接包含 `generated/hint_tables.rs` 和 `generated/lexer_tokens.rs`。
4. `GENERATED_RUST_TABLES` 仅描述第 2、3 步共同涉及的三个路径；现有实现没有遍历该常量来完成生成、检查或 `include!`。

## 数据与状态

常量保存三个 UTF-8 字符串字面量引用，顺序与 `parsergen/generate.rs::GENERATED_OUTPUT_NAMES` 的主表、Hint 表、token 表顺序一致。字符串带有 `generated/` 前缀，语义基准是 `pkg/parser` 目录；常量本身不把相对路径解析为 `Path`，也不检查文件是否存在。

这里没有运行时状态、缓存或懒初始化。三份实际产物是仓库中的独立 Rust 源文件，并带有 `@generated by astersql-parsergen; do not edit` 标记。清单与生成器的 `GENERATED_OUTPUT_NAMES` 当前是两处重复声明，编译器不会自动保证二者同步。

## 依赖与调用关系

[`Cargo.toml`](./Cargo.toml) 将本目录定义为 `astersql-parser`，库入口是 `lib.rs`；`astersql-parsergen` 仅列在 `[dev-dependencies]`，因此普通库依赖图不要求运行或链接生成器。生成器自身由 [`parsergen/Cargo.toml`](./parsergen/Cargo.toml) 定义为同时包含库和 `astersql-parsergen` 二进制的独立 crate。

上游装配边是 `pkg/parser/lib.rs -> pub mod generate -> include!("generate.rs")`。对 `GENERATED_RUST_TABLES` 的 RustCodeGraph 精确查询未建出符号节点，仓库级 `rg` 也只命中定义本身，所以目前没有已证实的直接消费者。

下游逻辑关系不是函数调用，而是清单中的路径对应：`lib.rs` 消费三份文件，`parsergen/generate.rs` 生成或校验三份文件，`parser_generated_sources_aster_unit_test.rs` 检查三份文件存在且由 `lib.rs` 静态包含。不能据此声称这些代码调用了本常量。

## 错误处理与边界

本文件没有 `Result`、panic 或 I/O，因此不会自行报告路径拼写、文件缺失、内容陈旧或清单漂移。若路径写错但没有调用方读取该常量，普通构建甚至可能不受影响；实际构建是否成功取决于 [`lib.rs`](./lib.rs) 中独立写出的 `include!` 路径。

生成阶段的错误边界由 `parsergen/generate.rs` 承担：文法读取、解析、分析表构造、目录创建和文件写入错误会带操作及路径上下文；检查阶段区分 `Missing` 与 `Stale`，其他读取错误直接传播。`parsergen/main.rs` 将失败打印到标准错误并返回失败退出码。

清单只覆盖 parsergen 的三个 Rust 表输出，不包括手写 parser 逻辑、`.astergram` 输入、Go 的 `parser.go`/`keywords.go`，也不表示 `generated/` 下未来任意文件都会自动纳入构建。

## 并发与资源生命周期

本文件只有不可变静态数据，没有锁、原子量、线程、异步任务、通道、事务、文件句柄或堆分配。读取常量可跨线程共享，生命周期覆盖整个进程。

文件生成时的临时 `String`、文法模型和文件 I/O 属于 `astersql-parsergen`，不由本文件持有。普通 parser 运行时使用编译进二进制的生成表，也不会打开清单所列路径。因而本文件没有清理协议或资源泄漏路径。

## 与 Go 版本的对应关系

同路径 [`generate.go`](./generate.go) 只包含 `//go:generate ./genkeyword`，用于生成 Go 关键字表 `keywords.go`；它不枚举 Go yacc 解析表，也不等价于 `GENERATED_RUST_TABLES`。相邻 `generate_keyword/genkeyword.go` 读取 `parser.y` 的关键字段并写 `keywords.go`，其独立测试 `generate_keyword/genkeyword_test.go` 只验证关键字行提取。

Rust 侧已经采用不同维护链：`.astergram` 输入交给 `astersql-parsergen`，输出三份静态 Rust 模块并由 `lib.rs` 包含；目标常量只是这条 Rust 链的清单。二者可对应到“显式维护生成代码”这一目的，但输入、输出、执行命令和实现均不同，不应把 Go 的 `go:generate` 行为移植推断到该常量上。

## 扩展指南

- 新增或移除 parsergen 输出时，应同步审查 `GENERATED_RUST_TABLES`、`parsergen/generate.rs::GENERATED_OUTPUT_NAMES`、`generate_outputs` 的构造顺序、`lib.rs` 的 `include!` 接线和 `parser_generated_sources_aster_unit_test.rs` 的预期集合。
- 若希望让清单成为真实单一事实来源，需要显式改造生成器或契约测试来消费它；在此之前不要删除其他位置的路径声明，也不要假设修改本常量会改变生成或编译行为。
- 生成器行为测试继续放在独立 [`parsergen/generate_aster_unit_test.rs`](./parsergen/generate_aster_unit_test.rs)，parser crate 的静态消费契约继续放在独立 [`parser_generated_sources_aster_unit_test.rs`](./parser_generated_sources_aster_unit_test.rs)，不要把测试嵌入本生产文件。
- 路径变化会影响源码包含、发布包内容和维护命令，兼容性风险高于本常量本身的表面改动；必须同时验证产物存在、内容无漂移和普通构建不依赖 `OUT_DIR`/`build.rs`。清单读取本身没有可观测性能风险。
