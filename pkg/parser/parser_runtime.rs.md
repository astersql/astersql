# `pkg/parser/parser_runtime.rs`

## 文件定位

本文件是 `astersql-parser` crate 的主 SQL LALR(1) 解析运行时。它不定义 SQL 文法和具体 AST（抽象语法树）节点，而是把词法器产生的 token 送入生成的状态/动作表，在规约时调用独立的语义动作层构造 AST。组装路径是 [`lib.rs`](lib.rs) 的 `parser` 模块依次 `include!` [`generated/main_tables.rs`](generated/main_tables.rs) 与 [`parser.rs`](parser.rs)，后者再包含 [`parser_value.rs`](parser_value.rs)、[`parser_semantic_support.rs`](parser_semantic_support.rs) 和本文件。因此，本文件中的私有生成表引用、`Parser`、`yySymType`、`Rhs` 与 `parser_actions` 都处于同一个模块作用域。

crate 边界由 [`Cargo.toml`](Cargo.toml) 确定：包名为 `astersql-parser`，库入口是 `lib.rs`，直接依赖拆分出的 AST、字符集、MySQL 兼容、错误、类型等 parser 子 crate。本文件自身没有条件编译项；它通过 crate 入口被无条件编入库。文件头虽然保留“Code generated by goyacc”来源说明，但当前 Rust 运行时会消费 `parsergen` 产出的 Rust 稀疏表，并把语义动作委派给手工分组的 `parser_actions`。

## 核心职责

- `yyLexer` / `yyLexerEx` 定义解析运行时与词法器之间的协议：读取 token、累计错误/警告、暴露 SQL mode、位置与原始语句文本，并可在每次规约后接收回调。
- `generated_main_symbol` 与 `generated_main_action` 对生成的稀疏表提供有界查询；找不到 token、状态或列时返回“无动作”，而不是越界。
- `yySymName` 和 `yylex1` 完成 token 名称诊断、EOF 归一化以及调试输出。
- `yyParse` 执行移进、规约、接受、错误恢复和提前终止；语义动作不内嵌于状态机，而由 `parser_actions::apply` 按稳定 `RuleId` 分派。
- `yyParse` 借用并归还 `Parser.cache`，避免长 SQL 每次重新分配解析栈；无论成功、失败还是扩展词法器提前终止，闭包退出后都会清空并归还该缓冲区。

## 主要符号

- `yyXError { state, xsym }`：兼容生成器布局的语法错误定位键。目前本文件的运行时不读取错误消息表；语法错误文本由 `yyLexer::Errorf` 的实际实现根据扫描器位置生成。字段私有，类型公开主要是生成代码兼容边界。
- `account`：从 `token` 模块公开再导出的 token 常量，保持既有生成 API 可见性。
- `yyEOFCode: isize = 0`：运行时统一使用的输入结束 token。
- `generated_main_symbol(token) -> Option<usize>`：在有序的 `GENERATED_MAIN_XLAT` 中二分查找外部 token 编号对应的内部符号列。
- `generated_main_action(state, symbol) -> i32`：先按状态取稀疏行，再按符号列二分查找编码动作；缺失统一返回 `0`。`GENERATED_MAIN_ACCEPT` 表示接受，正值编码移进/转移目标加一，负值编码规约编号加一，零表示错误或缺失动作。
- `yyDebug`：进程级可变调试等级；本文件只在 `yylex1` 中以不安全读取检查 `>= 3`，没有公开设置接口。
- `yyLexer`：解析器所需的基础 trait。`Lex`、`Errorf`、`AppendError`、`AppendWarn`、`Errors` 必须实现；语句文本、SQL mode、Hint 位置、扩展 trait 转换和跳过位置记录均有保守默认值。
- `yyLexerEx: yyLexer`：增加 `Reduced(rule, state, lval) -> bool`。返回 `true` 会让 `yyParse` 返回 `-1`，用于在规约边界提前停止。
- `yySymName(c) -> String`：已知 token 返回 `GENERATED_MAIN_SYMBOL_NAMES` 中的名称，未知 token 返回十进制编号。
- `yylex1(yylex, lval) -> isize`：调用 `Lex`，把所有非正返回值折叠为 EOF，并在高调试等级输出 token 与语义值偏移。
- `yyParse(yylex, parser_state) -> isize`：主状态机。返回 `0` 表示接受，`1` 表示表/栈不变量失败或语法恢复失败，`-1` 表示 `yyLexerEx::Reduced` 请求提前终止；语义动作也可通过 `Err(status)` 返回自己的非零状态。

## 执行流程

1. 上游 [`yy_parser.rs`](yy_parser.rs) 的 `Parser::ParseSQL` 重置参数、扫描器、结果与语义完整性状态，临时取出 `self.lexer`，再调用 `yyParse(&mut lexer, self)`；返回后收集警告与错误并把扫描器放回。
2. `yyParse` 用 `mem::take` 取得 `Parser.cache`，清空后压入默认 `yySymType` 作为状态 0 的栈底；`lookahead = -1` 表示尚未读取前瞻 token，`error_flag = 0` 表示不在恢复期。
3. 每轮从栈顶 `yys` 取得状态。没有前瞻时先重置 `parser_state.yylval`，再由 `yylex1` 读取 token；token 经 `generated_main_symbol` 转成内部符号，未知 token 使用超出表宽度的哨兵列，最终得到动作 0。
4. 动作为 `GENERATED_MAIN_ACCEPT` 时返回 0。正动作是移进：移动 `yylval` 入栈、把动作减一解码成新状态、消费前瞻，并将恢复计数逐次减至 0。
5. 负动作是规约：从 `GENERATED_MAIN_REDUCTIONS` 取左部符号与右部长度，从 `GENERATED_MAIN_LEGACY_RULES` 取传给兼容回调的旧规则号，从 `RULE_IDS_BY_REDUCTION` 取稳定动作标识。任何映射缺失或右部长度越过栈底都会追加解析错误并返回 1。
6. 运行时计算右部全部 `semantic_complete` 的合取，创建规约值，并先继承 `$1` 的偏移与标识符。随后以 `Rhs` 和 `parser_actions::Context` 调用 `parser_actions::apply`。动作未处理时采用 goyacc 的默认 `$$ = $1`，但用移动而非克隆承载动态 AST；若该规则本应有语义动作却未处理，则把规约结果标记为语义不完整。
7. 弹出右部后，依据新栈顶状态和规约左部符号查 goto。goto 不是正编码即报错返回 1。若词法器未要求跳过位置记录，则调用 `yySetOffset` 把规约偏移写入表达式节点；随后设置新状态并调用可选 `Reduced`。回调要求停止时返回 -1，否则把规约值压栈继续。
8. 动作为 0 时进入与 Go goyacc 对齐的三阶段恢复：首次错误只追加一次空格式错误；然后把 `error_flag` 设为 3，逐层弹栈直到找到能移进合成 `error` 符号的状态；恢复期内若仍无动作则丢弃当前前瞻，EOF 时失败。连续三个正常 token 移进后才退出恢复期。
9. 内层闭包结束后，`yyParse` 无条件清空值栈并归还 `parser_state.cache`，再返回状态码。`Parser::ParseSQL` 只有在状态为 0、扫描器无错误、语义结果完整且语句数吻合时才交付 AST。

## 数据与状态

解析栈是 `Vec<yySymType>`，单个元素同时保存 LR 状态 `yys` 与偏移、标识符、动态辅助值、表达式、语句和 `semantic_complete` 标记；其定义在 [`parser_value.rs`](parser_value.rs)。这与 Go 将状态和值放在一个 `yySymType` 切片中的形状一致，避免维护两套并行栈。

`lookahead` 使用 `-1` 表示“需要调用词法器”，使用 `0` 表示 EOF；外部 token 通过 `GENERATED_MAIN_XLAT` 映射到内部列。生成数据位于 [`generated/main_tables.rs`](generated/main_tables.rs)：`GENERATED_MAIN_PARSE_TABLE` 是按列排序的稀疏动作行，`GENERATED_MAIN_REDUCTIONS` 保存规约左部和长度，`RULE_IDS_BY_REDUCTION` 连接稳定语义动作标识，`GENERATED_MAIN_LEGACY_RULES` 保持 Go 回调规则号，`GENERATED_MAIN_ACTION_REQUIRED` 供测试检查动作覆盖率。

`Parser.cache` 在 [`yy_parser.rs`](yy_parser.rs) 的 `New` 中预分配 200 个元素容量。运行时每次只暂时取得其所有权；结束时清空长度但保留容量。`parser_state.yylval` 保存当前 token 的语义值，而规约产物在入栈前是局部 `reduced_value`。`error_flag` 只属于一次 `yyParse` 调用，不跨解析残留。

## 依赖与调用关系

上游生产调用边是 `Parser::ParseSQL`（[`yy_parser.rs`](yy_parser.rs)）→ `yyParse`；更外层公开入口 `Parser::Parse`、`Parser::ParseOneStmt` 和 `ParseSQLWithWarnings` 都汇入 `ParseSQL`。真实词法器 `Scanner` 在 [`lexer.rs`](lexer.rs) 实现 `yyLexer`：`Lex` 产生 token，`Errorf` 构造带扫描位置的错误，`AppendError`/`AppendWarn` 写入各自向量，`Errors` 返回两类诊断，且提供 SQL mode、Hint 位置和位置记录开关。

`yyParse` 的直接下游包括：本文件的 `yylex1`、`generated_main_symbol`、`generated_main_action`；[`generated/main_tables.rs`](generated/main_tables.rs) 的六组生成常量/表；[`parser_value.rs`](parser_value.rs) 的 `yySymType` 与 `Rhs`；[`parser_actions`](parser_actions/) 的 `apply`、`Context::new`、`has_semantic_action`；以及 [`yy_parser.rs`](yy_parser.rs) 的 `yySetOffset` 和 `Parser.cache/yylval`。

RustCodeGraph 索引确认本文件包含 43 个符号，并显示它在 crate 的 include 组合后被大量解析相关文件间接使用。精确图命令因 Rust/Go 同名生成符号未返回可用 callers/callees 边，故生产调用边又由 `rg` 核验：唯一非测试直接 `yyParse` 调用位于 `yy_parser.rs:408`；其他直接调用均在独立测试文件中。

## 错误处理与边界

- token `<= 0` 都被视为 EOF；未知正 token 不会越界，而会走动作 0 并触发语法恢复。
- 生成表不一致（规约、旧规则号或 `RuleId` 缺失）、规约弹栈越过栈底、goto 非正都被视为内部解析失败：通过 `AppendError(Errorf(...))` 记录明确内部错误并返回 1。
- 普通语法错误故意以空格式调用 `Errorf`，因为与 Go 一样由 `Scanner` 当前行、列和 near-text 生成最终诊断；恢复期间不会为每个被丢弃 token 重复追加错误。
- 错误恢复只在某个剩余栈状态能移进合成 `error` 符号时继续；栈耗尽或恢复期遇到 EOF 都返回 1。
- `values.last().expect(...)` 表达内部不变量：初始化后栈不应为空，成功规约也必须留下 goto 基状态。可控输入错误走显式返回路径，不依赖这些断言。
- `parser_actions::apply` 的错误状态原样返回；未处理动作不会伪造完整结果。最终还有 `Parser::ParseSQL` 的语句计数和 `semantic_complete` 双重门禁。

## 并发与资源生命周期

本文件不创建线程、异步任务、锁、通道、事务或外部 I/O。一次 `yyParse` 通过 `&mut dyn yyLexer` 和 `&mut Parser` 独占词法器与解析状态，因此同一个实例不能在安全 Rust 中被并发调用；不同 `Parser` 实例之间的解析栈和诊断互不共享。

主要资源是 AST/语义值所有权和栈容量。移进用 `mem::take` 从 `parser_state.yylval` 移动值，默认规约用 `Rhs::take_default` 移动 `$1`，避免克隆 `Box<dyn Node>` 等动态对象；弹栈或最终清空会正常释放未进入结果树的值。`Parser.cache` 的容量跨调用复用，但元素在每次结束时清空，因此错误或提前终止不会把旧语义值带入下一次解析。

唯一全局可变状态是 `static mut yyDebug`。当前没有公开写入路径，读取被局限在 `yylex1` 的 `unsafe` 块；若未来允许运行时修改，必须先改成原子值或其他同步机制，否则并发读写会产生数据竞争风险。

## 与 Go 版本的对应关系

直接对照文件是 [`parser.go`](parser.go) 的生成运行时。Rust 保留了 Go 的主要契约：`yyLexer`/`yyLexerEx` 方法集合、非正 token 折叠为 EOF、稀疏动作表驱动、正移进/负规约/零错误、三阶段错误恢复、忽略生成器错误消息而委托 Scanner、规约后 `Reduced(rule, state, lval)` 返回真即 `-1`，以及解析栈在 `Parser.cache` 中复用。

实现形态有几处明确差异：Go 的巨型 `switch r` 语义动作被拆到 `parser_actions::apply(RuleId, Rhs, Context)`；Rust 同时保留 `GENERATED_MAIN_LEGACY_RULES`，只用于向 `Reduced` 传递兼容规则号。Go 通过类型断言获得可选 `yyLexerEx`，Rust 通过 `yyLexer::as_extended` 显式返回 trait object。Go 会扩容缓存切片并维护 `yyVAL` 指针；Rust 的 `Vec` 自动扩容，规约值为局部所有权对象，结束后归还空栈容量。Rust 还增加生成表边界检查与 `semantic_complete` 门禁，以避免缺失语义动作时错误宣称成功。

Go [`parser_test.go`](parser_test.go) 的 `TestSideEffect` 验证错误 SQL 后同一个解析器仍能成功解析下一条 SQL，与 Rust 在每次调用中重建局部前瞻/恢复状态并清空归还缓存的设计目标一致。Go 的生成文件不是 Rust 构建输入，只是移植语义的对照基线。

## 扩展指南

- 新增或修改 SQL 文法时，不应直接手改本运行时的动作编号。应更新文法/生成器产物，使 `GENERATED_MAIN_XLAT`、动作表、规约表、稳定 `RuleId` 映射和动作需求位图同步，再在 `parser_actions` 中实现对应语义动作。
- 新增语义动作要保持 `Rhs` 的一基 `$1..$n` 约定、所有权移动策略和 `semantic_complete` 传播；同时扩展独立的 `parser_3_aster_unit_test.rs` 或相应 `parser_actions/*_test.rs`，不得把测试内嵌进本生产文件。
- 修改 token 归一化、动作编码或错误恢复时，应同步核对 Go `parser.go` 的 `yylex1`/`yyParse`，并至少覆盖 EOF、未知 token、恢复后继续解析、接受/失败状态码。改变表编码会同时影响 parsergen 与生成表，兼容风险高。
- 修改 `yyLexer` 时要同步 `Scanner`、测试词法器和所有默认方法调用方。尤其应保持 `Errors` 的 `(warnings, errors)` 顺序与 `Parser::ParseSQL` 解构一致；新增必需方法会破坏全部实现者。
- 修改缓存或所有权路径时，应保留“所有退出路径归还 cache”不变量，并用长语句重复解析测试确认指针/容量复用；错误路径还需对照 Go 的 `TestSideEffect`，防止残留状态污染下一次解析。
- 修改 `yyDebug` 前应先解决全局并发安全；修改位置记录必须同时检查 `skip_position_recording` 与 `yySetOffset`，避免对明确禁用位置记录的调用重新写入偏移。
