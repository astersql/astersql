# `pkg/session/runtime/pg_schema.rs`

数据库内PostgreSQL namespace的持久身份、owner、USAGE/CREATE事实、search_path绑定与原生关系名桥接。Namespace记录保存在现有共享KV，临时关系身份只归当前连接；不为PG namespace另建原生数据库。

## 数据库授权消费者

CREATE SCHEMA在写入namespace前调用`pg_require_database_privilege(4)`，与共享数据库CREATE查询一致；非root CREATE SCHEMA AUTHORIZATION其他角色仍保留现有局部门禁。`pg_allocate_temporary_identity`在每次临时关系分配前调用`pg_require_database_privilege(2)`，撤销TEMPORARY会拒绝新的临时对象，不删除已有临时表。

`pg_bind_relation`先处理当前连接未限定schema的本地临时表，保持其遮蔽永久关系和撤权后的已有表可用；永久对象仍按有效search_path与namespace USAGE/CREATE事实绑定。ACL事实未知不会转换成无权限false，bootstrap管理路径保留历史兼容边界。

聚焦回归：`pg_catalog_test::cat14_17`；namespace owner/绑定既有回归分别由cat14_13、cat14_14及pg_schema_test维护。类型/函数owner类别不属于数据库ACL事实扩展。


## 类型owner（目录任务15）

PgStandardSchema复用同一KV记录保存逐类型bootstrap owner及按数据库ID的显式owner覆盖。标准域内部ID与内置类型OID分别存储，避免编号碰撞。server传入已有COLUMN_TYPES声明；新记录初始化在同一事务登记真实bootstrap稳定角色OID，旧记录只登记稳定声明，不补缺失owner。查询只合并当前数据库覆盖，不更改标准视图owner。

管理员ALTER TYPE/DOMAIN OWNER仅处理已注册类型，类型身份不变；内置基础类型的数组owner同事务同步，直接修改数组或用DOMAIN修改非域为42809。共享角色不存在42704，非管理员42501，事务内由现有server DDL门禁拒绝。目录仅在读取缺源typowner时0A000，标识/name继续可读，外连接未匹配为SQL NULL。独立pg_schema_test::cat14_15_historical_type_owner_is_not_backfilled及server cat14_15覆盖真实KV升级/显式迁移和reader协议行为；不开放CREATE TYPE/DOMAIN。

## 命名空间授权（目录任务18）

Namespace的同一PgNamespaces记录新增可空grants，保存稳定grantor/grantee OID、USAGE(1)/CREATE(4)及grant options。新建schema同事务保存真实owner默认ACL；历史缺grants或owner不能从名字集合回造历史授权，nspacl/has_schema_privilege拒绝0A000。PgNamespaceFact.privilege_fact复用共享PgDatabaseFact的ACL校验/继承判断，文本codec按UC顺序；search_path及关系绑定对完整ACL沿同一有效权限判断，旧内置namespace保留原生执行兼容边界但不伪造可展示ACL。Privileges规范化旧Usage/RevokeAll API，经同一KV原子更新、真实grantor选择、RESTRICT/CASCADE；owner变更合并重写ACL身份，rename保留记录、drop移除记录、角色删除检查悬空引用。独立cat14_18_namespace_acl_provenance_atomicity_and_lifecycle覆盖缺源/损坏、失败不提交和重建身份。

管理员namespace事实与授权只读取既有稳定角色名字映射，不因无关旧原生账户尚无完整PG声明而中断。内部身份载体的属性保持unknown，不作为pg_roles展示默认值；非管理员授权和函数查询仍使用真实完整角色/继承事实。既有owner撤权测试显式创建PG角色以固定其非超级用户政策；内置information_schema尚无持久owner/grantor时acl_available=false，标准对象身份与布局仍可读。


## 表授权（目录任务19）

TablePrivileges分派至表ACL共享消费者；旧RelationPrivilege无列形式也走相同ACL事实，带列形式保留原适配器。角色身份读取供bootstrap管理路径惰性复用，不要求无关legacy角色已有完整PG属性。

表/列/约束标准视图的既有可见性消费者对有来源PG表ACL复用同一model-snapshot权限判断，保留owner独立可见及原精确列授权来源。权限集合与PG18 information_schema.sql一致：tables排除MAINTAIN，columns仅arwx，约束可见排除SELECT。避免PG表GRANT不再写native后导致既有标准目录漏行。

## 2026-11-06 列授权事实与查询（任务20）

TablePrivileges.columns将列ACL接入原SchemaUtility worker；标准column/table/constraint可见性优先使用新共享列事实，并保留旧native列桥接的历史行为。新PG列不从mysql.columns_priv推断ACL。历史RelationPrivilege局部API也转入同一TablePrivileges列事务，避免保留第二条写入事实路径。

## 类型授权（任务22）

任务22：同一PgStandardSchema记录新增type_acl_initialized及按数据库ID/类型OID保存的type_acl_overrides。新建标准记录显式初始化默认类型USAGE来源；serde历史缺字段为false，不在重连或读取时回填。owner事实与ACL独立。

任务23：同一 PgStandardSchema KV 记录新增函数 ACL 初始化来源标志、初始及数据库覆盖映射，只有新初始化设置默认来源；历史缺字段不回填。命名空间事实应用当前库函数 owner/ACL 覆盖。FunctionPrivileges 分派到共享 pg_function，ALTER FUNCTION OWNER 同事务改写显式 ACL，保持身份和库隔离。
