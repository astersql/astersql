# `.rs.md` Go/Rust 差异对抗审查计划

目标：从全量文档中识别可观察的 Go/Rust 行为差异，先用小规模反例证明，再逐项收敛 Rust 行为与测试。

范围：盘点仓库全部 2,576 份 `.rs.md`；本轮包含 42 个小任务：六个单行为的失败测试与修复任务，以及 36 个只读的单断言对抗审查任务。`inventory.tsv` 是全量发现索引，`prompt.md` 和编号文件是本轮可执行任务。文档中的差异陈述是待审假设，执行时必须重新对照当前 Go/Rust 源码及测试。

范围外：没有本轮反例和生产路径证据的大型子系统补建，以及全量索引中未进入这 42 项的候选。只读任务可以将所有权、接口形状、命名或并发实现差异判定为非行为缺口；后续仍从索引逐条形成小批次。

假设：`docs/docs-manifest.md` 列出本仓库业务 Rust 文件的说明文档；同路径 Go 文件通常提供迁移基线。当前 RustCodeGraph 索引覆盖 Go 与 Rust 源码，文档不在索引中。`AGENTS.md` 所述 `.agents/skills/tidb-verify-profile` 在当前工作树缺失，执行时仍须按其 Ready 要求运行 `make lint`，并记录该技能缺失。

## 设计决策

- 先核验反例，再修补窄行为；若文档差异已消失，改正说明或测试即可，不引入无意义代码。
- 每个编号任务只对应一个断言或一个可观察合同。行为变更先有反例；其余候选先做只读对抗审查，给出证实、反驳、仅实现形态差异或证据不足的结论。
- 按同一生产文件与测试文件的写入冲突排序。不同 crate 的修复可同批执行；只读任务同批不写源码或共享结果文件。

## 架构说明

- BR KMS URL 解析在 `br/pkg/task/encryption.rs`；Dumpling 一致性控制在 `dumpling/export/consistency.rs`、配置查询在 `sql.rs`，主导出入口在 `dump.rs`。
- `pkg/session/runtime/import_file.rs` 处理 split-file，`import_compression.rs` 处理普通文件/压缩文件导入；对应 Rust 行为测试独立于生产源文件。
- Go 基线来自对应 `.go` 与 Go 测试。只把 Go/Rust 同一用户输入下的结果差异当作修补依据；不得用编译成功或零测试替代行为证据。
- 只读审查的交付是该会话最终回复中的源码行、调用链和现有测试证据；不运行 Cargo，也不声称已证明动态行为。需要运行时反例时，提出单独的失败测试任务。

## 开发策略

- 每个行为变更先加能在当前 Rust 上失败的回归断言，保存失败输出，再作最小修复并运行同一断言。只读任务逐条尝试推翻文档叙述，禁止在审查中顺手改代码。
- 遵守 `AGENTS.md`：Rust 测试独立文件、保留 PingCAP 版权、修复后补 AsterSQL 版权、先 `cargo fmt --all` 再验证；生产修改逐项记录 Go 差异或必要接线依据。
- 代码交付使用 Ready 检查：聚焦 Rust 测试和 `make lint`；若工具或环境不可用，记录退出码及未验证内容，不把不可用当作通过。
- 本轮没有 Go 源码或 Bazel 元数据修改；若执行中增加 Go import、新顶层 Go 测试或其他 `AGENTS.md` Bazel 触发项，先运行 `make bazel_prepare`。

## 全量发现索引与局限

`inventory.tsv` 一行一文档，包含路径、Go 对照段落是否存在、显式差异措辞、行为限制措辞及证据行号。该索引由全文规则扫描产生，覆盖 2,576 份文档；它不证明每个候选仍与当前源码一致，也不表示未命中者已对齐。扫描结果中 2,565 份有“与 Go 版本的对应关系”标题，556 份命中“主要/已确认差异”等措辞。本轮 42 项是优先级筛选，不代表已审完其余文档；后续从索引另开小批次。

## 验收原则

批次顺序和文件冲突以 `prompt.md`、编号任务文件为准。代码任务必须提供 Go/Rust 基线、修复前失败、修复后通过、有效测试数、退出码、diff 自审和未验证项；只读任务提供源码行、生产可达性、反例与证据边界，不需要构建配置。已知 Go 旧回归失败可按 `AGENTS.md` 记录而不阻塞 Rust 任务。
