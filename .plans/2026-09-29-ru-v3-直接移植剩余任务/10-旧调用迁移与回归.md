## Surprises & Discoveries

Go `adapter.go:1934` 的 `finalizeStatementRUV2Metrics` 只同步 coprocessor response bytes。Rust 此前按 `RUVersion != 3` 使用旧公式并直接发布，与新的 statement snapshot 重复或在未完成时提前发布。RU v3 是公式版本，不是要求 domain RUVersion 取 3；Go 客户端版本保持 1/2。

当前真实 prepared SELECT 通过 `PreparePlannedKVSelect` → `ExecutePreparedPlannedKVSelectThroughAdapter` → `ExecStmt`，可获得一次终态发布。普通 canonical dispatch 没有统一进入该链。最初新增普通 `SELECT 1` 测试实际运行失败：期望 1 次发布，实际 0 次；未修改这条 dispatch 路径。已保留独立 `go_merge_20_187_195_197_production_ru_unbridged_sql_has_no_estimated_publication` 测试，在 SELECT 1、INSERT、ANALYZE 的真实执行中确认没有虚构/旧 RU 发布。该测试仅暴露缺口，不能替代正向 RU 生产桥接验收；桥接完成后应更新成 Go 等价正向断言。

prepared 优化路径对该 SQL 得到普通物理读计划，不能假设它一定是 PointGet。point 证据回归因此在 session 包使用真实 PointGet 类型、真实 catalog/编码 KV 行及 snapshot 来验证 `BuildExecStmt` → `Exec` → `Next` → EOF → `Close`，不伪造 RPC 字节；该测试不等同于证明所有 SQL 自动编译进入 point 快路径。
