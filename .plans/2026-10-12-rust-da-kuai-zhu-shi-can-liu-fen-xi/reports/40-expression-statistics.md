# Expression 与 Statistics 大块注释残留审计

## 范围与结论

- 输入：`reports/00-candidates.tsv` 中 `pkg/expression/**` 与 `pkg/statistics/**` 的全部 191 个候选。
- package 合同：两个目标树下均不存在 `doc.go`；因此以模块入口、生产实现、相邻可执行测试和 RustCodeGraph 索引为依据。
- 分类计数：部分实现且注释仍描述缺口 171；非执行测试档案 2；合法说明/生成器模板误报 18；已实现重复档案 0；完全未实现占位 0。
- 总体判断：Expression 的 generator 原始字符串是运行时生成输入；其余 Expression 长注释大多仍保存未被逐项证明的 Go 用例。Statistics 的 async-load 长说明对应真实执行测试；priority queue 只重建局部状态机；storage 的两个原始字符串明确是不参与执行的集成测试档案。

## 关键行为证据

- Expression generator：`compare_vec.rs`、`control_vec.rs`、`other_vec.rs`、`string_vec.rs`、`time_vec.rs` 和 `builtin_threadsafe.rs` 的模板均进入 `render`、`generate_dot_go` 或 `generate_one_file`；同目录测试检查生成内容、成对输出和 Go 语法。这些字符串必须保留。
- Expression builtin：string/time/regexp 的候选包含原 Go case 表，活动入口大量复用单一 `run_*_parity_suite`；这能证明内核有回归覆盖，但不能把每一段原 Go 断言认定为已经一一重建。尤其要保留 NULL、binary/charset/collation、时区/FSP/warning、向量化与逐行一致性作为后续验收边界。
- Expression collation/typeinfer：已有 hash、默认推导与若干 suite 覆盖；但候选中的完整冲突矩阵，以及 parser → preprocess → logical plan → FieldType 的端到端属性断言仍是注释。
- Statistics async load：五个 `#[test]` 使用真实 mock store/domain、SQL、ANALYZE、队列轮询、DROP 与 `load_needed_histograms`，长注释只是解释 workspace 适配与串行化约束。
- Statistics priority queue：活动测试覆盖 SQL 参数顺序、缺失表/过期分区校验、初始化/关闭/重排和若干 DDL 分派；注释中的 TestKit、DDL notifier、failpoint、running job 并发、分区统计变化和失败冷却集成路径仍未执行。
- Statistics storage：`gc_test.rs` 与 `read_test.rs` 的候选位于 `_GO_DRAFT_ARCHIVE`，编译时只是字符串。字符串后的测试只覆盖局部转换、时间戳或扫描窗口，不能替代统计系统表持久化和异步加载集成断言。
