# Rust 大块注释残留分析计划

目标：完整识别仓库中以行注释、块注释或字符串归档保存的非执行 Go/Rust 代码，逐项判断实现状态并形成可执行处置清单。

范围：扫描全部 Rust 源文件；覆盖连续代码形注释、Go 草稿原始字符串、机械迁移占位和不可执行测试参考文本。每个候选记录位置、来源意图、现有 Rust 对应实现、缺失行为、测试覆盖、风险及建议。分析阶段只新增审计报告，不修改生产代码、测试行为或已有注释。

范围外：本计划不直接删除注释、补齐实现、移植外部依赖或修复发现的行为缺口；这些工作应按审计结论另建聚焦实施计划。

假设：`.rustcodegraph/` 已建立且覆盖 Go/Rust 源码；初步保守搜索已发现 119 个含代码声明形行注释的 Rust 文件，并发现至少 20 个明确的 Go 草稿字符串/不可执行参考文件。该数字只是基线，不是完成上限。

## 设计决策

- 采用“两层发现”：确定性语法启发式负责建立候选全集，迁移标记词搜索负责补足原始字符串、块注释和非连续残留。
- 候选逐块归为：已实现重复档案、部分实现且注释仍描述缺口、完全未实现占位、非执行测试档案、合法说明/示例误报；不以“可编译”替代行为对齐判断。
- 分析按互斥路径分片并行，所有分片只写自己的报告；最终汇总任务统一去重、核对覆盖率并生成后续处置优先级。
- 对每个真实残留保留 Go 来源和当前 Rust 证据。若无法证明对应关系，标记“需来源提交核对”，不猜测已实现或可删除。

## 架构说明

- Rust workspace 入口为根目录 `Cargo.toml`，源码主要位于 `pkg/`、`br/`、`lightning/`、`dumpling/`、`cmd/`、`tests/` 和 `tools/`。
- 代码导航优先使用 `~/.rustcodegraph/bin/rustcodegraph`；索引不覆盖的注释、字符串和配置使用 `rg`、`awk` 与直接文件读取。
- 审计报告统一写入本计划目录的 `reports/`，字段和分类必须一致，便于最终机械核对。
- 正常许可证、Rustdoc、算法解释、SQL/协议示例和生成文件说明不能仅因行数较长而判为残留。

## 开发策略

- 本计划是只读代码审计，不改变行为，因此测试驱动开发不适用。
- 每个分片先读取候选清单，再检查 Go 来源、可执行 Rust、相邻测试和调用关系，最后写报告。
- 每个“可删除”建议必须有现有 Rust 实现与测试证据；每个“待实现”建议必须列出缺失的可观察行为，不能只写“代码被注释”。
- 完成证据以候选全集覆盖、分片零遗漏、分类理由和最终去重统计为准；不运行 Cargo，也不占用 Cargo 共享槽位。
