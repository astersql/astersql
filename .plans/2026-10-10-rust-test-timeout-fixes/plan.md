# Rust 单元测试超时修复计划

目标：定位并修复若干代表性的 Rust 测试超时，使默认 10 秒预算内完成，同时保留对应 Go 行为和测试意图。

范围：处理纯内存、无需外部 TiKV 的三类典型问题：固定墙钟并发测试、索引使用率采集热点与重复压力负载、session 测试的重复昂贵初始化；使用定向 nextest 计时验证。

范围外：RealTiKV 外部集群用例、已失败但未超时的断言、全工作区所有 18284 个测试的逐一优化。

假设：默认 nextest 在 10 秒终止测试；Go 代码是语义来源，但 Rust 测试无需通过固定等待或重复相同压力负载来证明语义。

## 设计决策

- 优先消除固定等待、重复工作和偏离 Go 数据所有权模型的额外锁，不通过扩大全局超时掩盖问题。
- 每项修改保留 Go 测试覆盖的并发、聚合和 SQL 结果断言；性能门槛以默认 nextest 不超时为准。

## 架构说明

- `pkg/statistics/handle/usage/indexusage` 的 session delta 应与 Go 一样由会话独占，report/flush 时转移给 worker。
- `pkg/store/mockstore/unistore/lockstore` 的并发测试验证读写交错与数据完整性，不应把十秒墙钟本身当作行为。
- `pkg/session/runtime` 使用内存 SQL domain；应复用单个 domain/session 或减少无意义重复初始化，但不得缩减 SQL 语义断言。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前记录当前超时或大于十秒的基线。
- 将实施步骤限制在基线证明的热点范围内。
- 测试真实并发、聚合与 SQL 行为，不只验证 mock。
