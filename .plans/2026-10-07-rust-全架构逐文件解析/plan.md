# Rust 全架构逐文件解析计划

目标：为仓库内 3381 个非测试 Rust 源文件逐一建立可追溯的中文逻辑说明，并汇总成分布式数据库整体架构图与阅读清单。

范围：纳入所有 `.rs` 生产候选；排除 `*_test.rs`、`*_tests.rs`、`test.rs`、`tests.rs`，以及位于 `test/tests/testdata/benches/fuzz` 目录的文件。每个源文件对应一个独立任务和一个同路径说明文档，最终生成模块化索引及整体架构说明。

范围外：不修改 Rust/Go 行为，不补实现、不修缺陷、不运行 Cargo，不把测试文件本身作为独立说明对象。

假设：RustCodeGraph 当前索引覆盖 7032 个 Rust 文件；生产候选通过上述稳定规则得到 3381 个。`stubs.rs`、生产目录中的 `mock`/`testutil` 可能参与编译，故保留并在文档中明确其真实角色。

## 设计决策

- 文档镜像源路径保存到 `docs/rust-architecture/files/<源文件>.md`，让源文件与说明一一对应且可机械校验。
- 单文件任务只写自己的说明文档，互不争用；每批最多 10 个任务。最终汇总任务在全部单文件文档完成后写架构图和阅读清单。
- 分析以 RustCodeGraph 的符号、调用边和源码为主；对未覆盖的 Cargo、Go 对照文件和配置使用 `rg` 与文件读取核验。

## 架构说明

- AsterSQL 是由根 Cargo workspace 组装的分布式 SQL 数据库。`cmd/tidb-server` 提供进程入口；`pkg/session`、`pkg/planner`、`pkg/executor`、`pkg/expression` 形成 SQL 接收、规划与执行主链；`pkg/distsql`、`pkg/store`、`pkg/kv` 连接分布式存储；`pkg/domain`、`pkg/infoschema`、`pkg/meta`、`pkg/ddl` 管理租户可见元数据和模式生命周期。
- `br`、`lightning`、`dumpling` 是备份恢复、批量导入、逻辑导出工具链；`tools`、`build` 是开发与构建辅助面。最终文档必须从真实入口、模块声明、调用关系和 Cargo 依赖验证这些关系，不把本节概览当作结论。
- `pkg/lib.rs` 是迁移期兼容门面，不能仅凭再导出结构判断业务归属；每份文档必须追到 canonical crate 或实际实现文件。

## 开发策略

- 本计划只创建文档，不改变行为，因此测试驱动开发不适用；以结构校验、链接校验、源文件覆盖率与抽样事实复核代替。
- 单文件说明必须覆盖：文件定位、核心职责、主要符号、执行流程、数据与状态、依赖与调用关系、错误处理与边界、并发与资源生命周期、Go 对照、扩展指南、验证依据。
- 对空实现、桩、兼容门面、生成代码或未接线模块必须如实标识，不得用预期设计替代当前代码事实。
- 每个结论至少给出源码符号、RustCodeGraph 查询或相邻 Cargo/Go 文件之一作为依据；无法确认的内容明确写为“未验证”，不得猜测。

## 文档规范

每个 `docs/rust-architecture/files/**/*.rs.md` 以源路径为标题，并依次包含固定的十一个二级标题。说明要给出关键类型/函数签名的语义、主流程的步骤、重要分支和不变量、错误传播、锁/任务/通道/事务等生命周期、上游调用者与下游依赖，以及新增功能时应接入的位置和应同步的独立测试文件。不要整段复制源码。

整体 `architecture.md` 使用 Mermaid 至少绘制：进程与工具拓扑、SQL 请求主链、元数据/DDL 链、存储与事务链、备份导入导出链。每条边必须能反向链接到至少一份单文件说明。`README.md` 按模块和关联目录提供可勾选列表，并报告总数、已完成数和排除规则。

## 执行与并行

前 3381 个任务均属于批次 1，任务之间无业务依赖且输出文件不重叠。执行技能在批次内使用容量为 10 的滚动并发窗口，自动补位，不需要人为拆成数百个顺序批次。批次 2 的整体架构任务依赖批次 1 全部单文件任务，避免基于不完整材料提前汇总。

## 验收

- 清单中的源文件集合与按本计划排除规则重新计算的集合完全一致，且恰有 3381 个。
- 每个源文件恰有一个任务和一个目标说明文件；不存在重复、漏项或多个任务写同一说明文件。
- 每份说明包含固定章节且链接回真实源文件；关键陈述能由列出的符号、调用边或配置证据复核。
- `architecture.md` 的所有子系统与边均能链接到逐文件说明；`README.md` 按模块分组并含 3381 个阅读复选框。
- 这是纯文档工作，不调用 Cargo，故 Cargo 共享槽位规则不适用；交付时按仓库 Ready 文档检查执行，不运行代码构建测试。
