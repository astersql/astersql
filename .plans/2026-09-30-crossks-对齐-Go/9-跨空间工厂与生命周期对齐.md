## 恢复调查结论与可恢复交接（2026-10-01）

本次已实际实现并验证工厂故事中的独立部分，不再以“缺全量 DDL”跳过实施。完成的 Go 来源：cross_ks.go createSessionManager 的 Store/池/注册/公共同步器/提交器组装，getOrCreateStore 的 SYSTEM 共享所有权，以及 SessionManager.close 的先关闭会话池、再停止循环、最后清理注册和独立 Store 的顺序。新增的 KeyspaceSessionFactory 与 TargetSessionStore 位于已有 Session runtime 的 session_factory.rs，明确没有选举或消费代码。为跨 crate 接线修改既有 RuntimeFactory.prepare、InfoCache.schema，common system_session 只新增真实 TransactionMDL 提取接口。旧 crossks_runtime.rs 的早期测试注入已全部撤回，无最终差异。原六组文件与 session.rs 旧生产安装点尚未删除或替换。

正常 owner 安装本身并不需要移植全量 action：现有 owner.NewOwnerManager、DdlOwnerLease、schedule_persisted 和 NormalDdlSchemaBarrier 足够组成一个后台 runner。真正的验收缺口是 runner 需要把队列中的已有合法 action 分派到可持久化处理器，并保留它们的错误、取消、升级和恢复语义。当前唯一生产 DurableJobExecutor 是 TableMode；公开的其他 DDL API 不满足该事务/编码接口。以下方案已经按实际代码排除，而非仅做全局符号搜索：

1. 复用 pkg/ddl/executor.rs::Executor/JobBackend：JobBackend 是提交、history/current、cancel 的前端接口；唯一生产实现 MemoryJobBackend 使用内存 map 并同步完成。DdlJob 是另一种模型，不能直接消费 decode_go_history_job 返回的 wire Job，更没有 DurableJobSession.with_transaction。
2. 复用 pkg/ddl/schema.rs::SchemaCatalog 或 table.rs::TableCatalog：它们修改简化内存结构，未接 KV mutator、schema diff、正常 DDL history 和单事务作业更新。逐项加持久化、在线多阶段及 rollback 不是 factory adapter 修复。
3. 把队列参数重放到 CanonicalSession/Domain 的现有 DdlMetadataService：canonical_domain.rs 的服务自行开始并提交 catalog 事务、同步公开表结构。它无法参加 job_worker.rs:289–330 的实际 worker 事务、重读校验和 owner 提交前复查。包装调用不能解决 schema/diff/job 非原子提交，也无法复用 Go 已分配 IDs/多阶段状态。
4. 建一个通用注册表/runner，但只注册 action 75：可以安全保存未支持作业并显式报错，但这只证明 fail-closed，不证明 Go 正常消费。遇到合法 CreateSchema/CreateTable 作业，当前处理器没有推进它们的办法；按 Go job_worker.go:1105–1265，合法 action 应分派到各处理器，只有真正无效的 action 才 Cancelled/ErrInvalidDDLJob。不能用默认 Cancelled 破坏合法作业，也不能静默忽略、仅按 type=75 查询、让权或宣称其他 action 已完成。
5. 复用旧 CrossKSDdlOwner、复制其消费代码或改名：直接违反已确认来源边界，且仍缺少普通 action 持久化状态机。

因此保留的阻塞比上次结论更具体：没有“正常 owner 可使用的 Go wire Job → 持久化 action handler”公共分派实现，现有接口也不能通过无损转换完成此职责。最小下一步决策是为此缺口制定独立的正常 DDL 持久化分派计划（先定义共享事务/完整 Job ABI、合法未实现与无效 action 的区别，再以至少一个非 75 作业及混合队列验证），或由用户明确改变本计划正常 DDL 等价的验收范围。不能默认接受仅 action 75 的生产服务。factory 的其余服务接线/循环 GC/Session validator 提交检查需跟该正常服务安装一起验收；本次只证明 validator 被公共 issyncer 持有和更新，未证明 canonical session 事务使用它。未因授权范围不足请求再次批准已做的接口修复；阻塞是具体执行语义缺口。
