# 执行 Codex 任务计划会话

将用户指定的 `prompt.md` 视为完整计划的调度入口。主会话只负责创建任务会话、等待、判定状态、恢复阻塞和启动最终回归；不执行任务内容，不修改代码或任务文件，不总结子会话的实现。

## 模型与项目

- 默认不询问模型。每个任务会话显式使用 `model: "gpt-6-sol"` 和 `thinking: "low"`。
- 用户明确指定模型或推理强度时，对所有新建任务会话应用该覆盖。
- 使用 `codex_app__list_projects` 按当前工作目录的绝对路径匹配项目。找不到匹配项目时停止，不猜测 `projectId`。
- 默认使用 `{ type: "local" }` 环境，让同一计划的会话共享当前项目状态。只有用户明确要求 worktree 时才改用 worktree。

## 读取计划

1. 读取用户指定的 `prompt.md`。未指定路径时，只在当前项目存在唯一合理的 `.plans/*/prompt.md` 时自动选择；存在多个候选时请用户指定。
2. 按 `# 批次 N` 和 `## 任务 N` 解析顺序，将每个任务下的 `text` 代码块作为该会话的完整初始提示词。不合并、删减、改写或补充任务提示。
3. 从提示词中解析对应编号任务文件的绝对路径，读取其批次、依赖和 `状态：`。`plan.md` 只读，主会话不修改任何计划文件。
4. 每个编号任务只能对应一个任务会话。不创建包含多个任务的“总实现会话”，不让主会话补做子任务。

## 批次调度

1. 严格按批次号从小到大调度。当前批次的所有可运行任务达到可接受状态前，不启动依赖它们的后续批次。
2. 同一批次使用容量为 10 的滚动并发窗口，而不是等待整波结束：先创建最多 10 个可运行任务会话；此后任一会话完成、进入待回归或转为暂不可运行时，立即从该批次待运行队列按任务顺序补位，直到活动会话重新达到 10 个或队列为空。
3. 使用 `codex_app__create_thread` 创建会话：标题使用 `prompt.md` 中的任务标题，初始提示词使用该任务的完整代码块，项目与环境按上述规则设置。
4. 使用 `codex_app__wait_threads` 等待当前活动会话。传入每个会话的 `hostId`、`threadId` 和最新 `afterCursor`；如果单次调用允许的目标数少于活动会话数，将活动集合分组轮换等待，但不得因此降低或暂停 10 个会话的实际并发。
5. 每次等待返回后，先按下方状态机处理所有已完成或需要关注的会话并更新活动集合，再立即补满并发窗口，然后才进行下一次等待。不得等其余旧会话全部结束后再创建下一组任务。
6. 子会话结束不等于任务完成。每次会话结束或需要关注时，按下方状态机判定；不复述子会话的代码、命令或结论。

滚动调度不变量：`活动会话数 <= 10`；只要当前批次仍有可运行的待创建任务且 `活动会话数 < 10`，就必须立即创建任务补位。

## 状态机

任务文件是状态来源，子会话最终文本只用于确认是否需要恢复执行。主会话只做以下判定：

- **已完成并删除**：对应编号任务文件已不存在。该任务完成，可满足后续依赖。
- **已完成，待回归**：任务文件保留且状态精确为 `已完成，待回归`。实现阶段视为完成，允许后续批次继续；将该会话加入最终回归队列。
- **已阻塞**：任务文件保留且状态精确为 `已阻塞`。进入阻塞恢复流程，不立即终止整个计划。
- **未完成**：文件仍为 `未开始`、保留 `已完成` 而未按契约删除，或会话结束但没有可判定状态。使用 `codex_app__send_message_to_thread` 继续原任务会话，要求完成剩余工作并严格更新/删除任务文件；不新建替代会话。

不根据子会话的自信描述将任务判为完成，不由主会话代为删除或改写任务文件。

## 阻塞恢复

阻塞不应自动中断整个计划。恢复必须在该任务的原会话中进行，主会话不自己实施修复。

1. 先等待同批次其他任务结束；如果阻塞来自共享文件、构建产物或同批次尚未完成的前置工作，完成后立即重试。
2. 使用 `codex_app__send_message_to_thread` 向原会话发送恢复指令，要求它重读任务文件中的阻塞证据，穷尽任务范围内的安全替代方案,并且可以扩大任务范围来突破阻塞，并区分：
   - 瞬时命令/构建/环境失败：重试或采用仓库已有替代验证。
   - 无关本任务的回归失败：实现和聚焦验证已完成时，按任务契约改为 `已完成，待回归`，不伪造通过证据。
   - 与其他任务的可合并冲突：在其他会话完成后基于最新工作区继续。
   - 真实缺失用户决策、权限或外部状态：保留 `已阻塞` 和具体证据。
3. 相同阻塞重复时不重复无意义命令。继续所有不依赖该阻塞项的当前批次和后续任务；依赖它的任务延后，并在其他可运行工作完成后再重试。
4. 只有当没有活动会话、没有任何不依赖阻塞项的可运行任务，且原会话已证明需要新的用户权限/决策或外部状态时，才停止等待用户。

恢复提示保持简短，例如：

```text
请继续执行原任务。重读任务文件中的阻塞证据，先基于当前共享工作区重试，并穷尽任务范围内的安全替代方案,并且可以扩大任务范围来突破阻塞。实现与聚焦验证已完成、仅剩无关回归失败时，按契约标记为“已完成，待回归”；只有真正需要用户决策、权限或外部状态时才保留“已阻塞”。
```

## 最终回归阶段

1. `已完成，待回归` 在实现批次中视为可继续，但不立即运行回归。
2. 只有所有非阻塞计划任务都已完成并删除，或进入 `已完成，待回归`，才启动最终回归。
3. 对回归队列中的每个任务，使用 `codex_app__send_message_to_thread` 恢复其原任务会话；不创建新回归会话，不在主会话运行测试。
4. 回归也使用容量为 10 的滚动并发窗口：任一原会话结束或暂不可运行后，立即恢复下一个待回归会话补位，不等待整组结束。使用 `codex_app__wait_threads` 等待；单次等待目标受限时分组轮换，但保持最多 10 个原会话实际并行。回归通过后由原会话删除任务文件；回归失败时由原会话在自身范围内诊断和修复，然后重试。
5. 回归后再次使用状态机判定。只有任务文件被删除才是最终完成；真实需要新用户决策/权限的回归失败可保留阻塞。

回归提示保持简短，例如：

```text
所有计划任务的实现阶段已结束。现在执行你的任务文件中延后的回归验证，基于当前最新共享工作区诊断并修复与本任务相关的失败。获得所需证据后删除该任务文件；只有真正需要用户决策、权限或外部状态时才标记为“已阻塞”。
```

## 停止与最终回复

- 所有编号任务文件都已删除时，计划完成。
- 只有存在不可突破的真实阻塞，且已无其他可运行任务时，计划才以阻塞状态停止。
- 主会话在调度过程中不输出子任务总结、代码摘要、测试摘要或进度叙述；只在需要用户解除真实阻塞时说明必要的决策或权限。
- 最终回复只给出整体状态：`计划执行完成。` 或 `计划未完成：N 个任务仍阻塞。`，不总结每个任务。
- 对每个成功创建的会话，最终回复仍必须单独输出 `::created-thread{threadId="..."}`；若创建返回 `clientThreadId`，输出对应的 `::created-thread{clientThreadId="..."}`。这些指令不是任务总结。

## 边界

- 此技能调度 Codex 项目会话，不创建自动化、分支、提交或 PR。
- 子任务的执行授权仅来自各自提示词和任务文件；阻塞恢复不扩大原任务范围。
- 主会话不使用 shell、编辑工具或测试工具实施计划；仅可用只读文件操作获取 `prompt.md`、任务文件和会话状态，并调用项目/会话管理工具。
