# Go 到 Rust 移植提示词指南

基于版本 2026-07-09 12:37 分对应的版本，回溯版本的时候参考这里。

本指南用于重复执行“筛选低依赖 package → 创建计划 → 分包收口 → 正式接入”的迁移流程。批量迁移是按 package 批次推进，不代表可以无人值守地自动修复 Rust 所有权、生命周期、并发、unsafe 或业务语义。

## 使用前提

- 从仓库根目录工作，并先阅读 `AGENTS.md`。
- 计划阶段使用 `./skills/create-task-plans/SKILL.md`。
- 执行阶段同时使用：
  - `./skills/do-task-plans/SKILL.md`：管理任务状态、阻塞记录和完成证据。
  - `./skills/run-rust-migration-batches/SKILL.md`：执行 inventory、schedule、probe、diagnose、fix、测试和正式接入。
- Go 源码和 Go 测试是行为权威；Rust 测试必须放在独立 `*_test.rs`。
- 不对全仓执行写入式 `fix --apply`，只修改当前 package。
- `plan.md` 创建后只读，进度只记录在编号任务文件中。

## 占位符

复制提示词前替换以下内容：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `<候选范围>` | 允许筛选的目录或 package 前缀 | `pkg/util` |
| `<计划名称>` | 简短中文计划名 | `低依赖-util-rust-迁移` |
| `<计划目录>` | `create-task-plans` 生成的目录 | `.plans/2026-07-11-低依赖-util-rust-迁移` |
| `<任务文件>` | 一个编号任务文件 | `<计划目录>/1-收口-xxx.md` |
| `<package>` | inventory 中的 package path | `pkg/util/paging` |
| `<slug>` | 将 package 中 `/` 替换为 `__` | `pkg__util__paging` |

## 提示词一：筛选候选并创建计划

用于开始新一轮迁移。该提示词只创建计划，不实现代码。

```text
请使用技能 `./skills/create-task-plans/SKILL.md`，为 `<候选范围>` 创建 `<计划名称>` 的 Go→Rust 迁移计划，本轮只规划，不实现。

开始前：
1. 阅读 `AGENTS.md`、`docs/rust-migration-workflow.md` 和 `./skills/run-rust-migration-batches/SKILL.md`。
2. 使用 RustCodeGraph、`target/rust-migration/inventory.json` 与 `target/rust-migration/schedule.json` 核对真实依赖；产物缺失时先运行 rust-migration inventory/schedule 的只读生成流程。
3. 对候选 package 运行 probe/diagnose，只把输出写入 `target/rust-migration/`，不要修改迁移源码。

候选优先级：
- 拓扑层低，内部依赖 0 或 1；
- Rust 行数不超过当前批次预算；
- 已有对应 Go 测试和独立 Rust 测试草稿；
- 生产 probe 已绿色，或只有少量明确的 module/import/name 错误；
- 优先纯函数、解析、常量、局部数据结构；
- 暂缓所有权/生命周期、并发、unsafe、数据库状态、网络和复杂错误模型。

选择 3–5 个真实候选，并记录每个 package 的拓扑层、内部依赖数、Rust 行数、测试文件和 probe 诊断。先让不同 package 在独立目录内完成收口，再单独创建共享 `pkg/lib.rs` 正式接入任务；会修改同一文件的任务不得放入同一并行批次。

生成 `<计划目录>/plan.md`、编号任务文件和 `prompt.md`。每个执行提示必须明确要求同时使用：
- `./skills/do-task-plans/SKILL.md`
- `./skills/run-rust-migration-batches/SKILL.md`

每个 package 任务必须包含：现有机械测试的失败验证、package-local 通过验证、Go 对照测试、probe 复验、精确文件范围和完成证据。正式接入任务必须运行聚焦 Rust 测试、`cargo test --lib` 和 `cargo check`。不要修改 Go 源码，不要加入提交步骤。
```

## 提示词二：执行一个 package 迁移任务

每个任务放到独立对话框执行。可直接使用计划生成的 `prompt.md`；若需手工发起，使用以下模板。

```text
请同时使用技能 `./skills/do-task-plans/SKILL.md` 和 `./skills/run-rust-migration-batches/SKILL.md` 执行 `<任务文件>`。前者管理任务状态、阻塞与证据，后者执行 Rust package 迁移流程。

开始前阅读 `<计划目录>/plan.md` 和 `<任务文件>`，确认依赖批次已完成。`plan.md` 只读，不得修改。

严格限制在任务文件列出的 package 和文件范围内：
1. 检查工作树并保留用户已有修改。
2. 运行任务定义的失败验证，确认失败原因与计划一致。
3. 对 `<package>` 运行 probe、diagnose 和 `fix --dry-run`；只有审查为 Go 等价的白名单修改才能对当前 package 执行 `fix --apply`。
4. 对照 Go 源码和 Go 测试人工收口剩余语义；不得删除 Go 分支、断言或边界用例。
5. Rust 测试保留在独立 `*_test.rs`；处理完成的 Rust 生产文件顶部增加 `// Copyright 2026 AsterSQL.`。
6. 运行 package-local Rust 测试、对应 Go 测试和 after probe。

获得任务要求的全部新验证证据后，在最终回复中报告证据并删除 `<任务文件>`。如果被阻塞，只把该任务状态改为 `已阻塞`，记录具体原因和已运行检查；如果全量验证仅因明确的无关修改失败，可改为 `已完成，待回归验证`，但不得删除任务文件。不要扩大任务范围，不要修改 `<计划目录>/plan.md`。
```

## 提示词三：执行正式 crate 接入任务

所有并行 package 任务完成后再使用。

```text
请同时使用技能 `./skills/do-task-plans/SKILL.md` 和 `./skills/run-rust-migration-batches/SKILL.md` 执行 `<正式接入任务文件>`。

开始前阅读 `<计划目录>/plan.md` 和任务文件，确认所有依赖 package 已分别获得：失败验证、package-local Rust 测试、Go 测试和 after probe 成功证据。缺少任一证据就停止并记录阻塞。

只按仓库现有模块布局修改共享入口；不要再次调整已验证的 package 生产语义，不要新增计划外依赖。依次运行：
1. 每个新模块的 `cargo test --lib <模块过滤串>`；
2. 对应 package 的 Go 测试；
3. `cargo test --lib`；
4. `cargo check`；
5. 差异审查，确认没有迁移调用方、删除测试或混入无关修改。

全部通过后报告模块路径、测试数量、命令退出码和差异审查，并按任务规则删除任务文件。若完整回归被无关工作树修改影响，保留任务文件并标记 `已完成，待回归验证`。
```

## 提示词四：分析阻塞，不实现修复

用于 probe 失败原因不明确，或任务可能超出原范围时。

```text
请使用 `./skills/run-rust-migration-batches/SKILL.md` 诊断 `<package>` 的迁移阻塞，只分析并报告，不修改生产源码。

读取 inventory、schedule、对应 Go/Rust 文件和测试；运行 probe 与 diagnose，把产物写到 `target/rust-migration/<slug>-blocked.*`。按根因族区分：module/import、name、type、trait、ownership/lifetime、unsafe、link/dependency 和级联错误。

报告：
- 直接根因与级联错误数量；
- 必须修改的最小文件集合；
- 是否超出当前任务范围；
- 是否需要新增依赖或设计决策；
- 建议继续、拆分新任务或标记阻塞。

不要执行 `fix --apply`，不要修改计划文件或任务状态。
```

## 提示词五：生成下一轮低依赖计划

当前批次完成并获得新的全仓汇总诊断后使用。

```text
请使用 `./skills/create-task-plans/SKILL.md` 基于最新 inventory、全仓汇总 report 和 schedule 创建下一轮低依赖 Rust 迁移计划。

先验证 schedule 的 package 覆盖率为 100%、依赖逆序数为 0、重复 package 数为 0。排除已正式接入、blocked、over_budget、当前工作树正在修改以及会争用同一入口文件的 package。优先从编号最小的可执行批次中选择有 Go/Rust 对照测试的 3–5 个 package，并对每个候选运行只读 probe/diagnose 验证难度。

计划仍采用“package-local 收口可并行，正式 crate 接入单独串行”的结构；在所有执行提示中明确要求同时使用 `do-task-plans` 和 `run-rust-migration-batches`。本轮只生成计划，不实现代码。
```

## 完成门槛

一个 package 只有同时具备以下证据才算完成：

- 失败验证符合预期；
- after probe 退出码 0；
- 对应 Go 测试通过；
- 独立 Rust 行为测试通过；
- Go/Rust 用例和边界对照无删减；
- 自动修复补丁已审查，人工根因已清零；
- 正式接入后聚焦测试、`cargo test --lib` 和 `cargo check` 通过。

局部报告不能覆盖全仓汇总报告。没有新的全仓汇总诊断时，只保存当前批次证据，不要据此错误解除其他 package 的阻塞状态。
