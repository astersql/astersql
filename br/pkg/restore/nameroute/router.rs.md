# `br/pkg/restore/nameroute/router.rs`

## 文件定位

构造精确库/表名称路由，校验规则集合及具体恢复对象的目标唯一性，生成可持久化的规范规则和 SHA-256 指纹。

## 核心职责

构造精确库/表名称路由，校验规则集合及具体恢复对象的目标唯一性，生成可持久化的规范规则和 SHA-256 指纹。只对原始源名称应用一次规则，不递归路由结果。

## 主要符号

`ObjectName` 用 schema/table 字符串表示库或表；`Rule` 保存 source/target。`Router::parse/new` 创建路由器；`route` 返回目标库、表和是否命中；`validate_targets` 检查对象集合。`rules`、`canonical_rules` 返回只读切片，`fingerprint` 返回 32 字节数组。`NameRouteError` 实现 Display/Error。

## 执行流程

构造时逐条校验名称与对象种类，用小写对象键拒绝重复源、重复目标和自映射；分别建立表与库 HashMap。路由先查表规则，再查库规则，库规则保留输入表名，否则原样返回。`validate_targets` 对源按小写键去重，再计算每个目标并拒绝不同源落到相同目标，包括重命名对象与未变对象的碰撞。

## 数据与状态

保留原始名称拼写用于输出；匹配键使用 Unicode `to_lowercase`。规范规则将每个标识符都用反引号包裹并转义内部反引号，按字符串排序；逐条把 UTF-8 字节长度编码为大端 u64，再连同字节内容输入 SHA-256。顺序变化不改变指纹；规范文本保留大小写，不能声称仅大小写变化的规则具有相同指纹。

## 依赖与调用关系

依赖同模块 parser 的解析及名称校验、标准库 HashMap/HashSet 和 `sha2`。任务层 `get_name_router`、`build_restore_name_plan` 使用此 API。冻结版本中后者仅在独立任务测试中被调用；任务配置和日志检查点指纹已有局部接线，不能外推完整快照/PiTR 名称计划生产消费。

## 错误处理与边界

直接传入 `Rule` 也必须经过名称验证；源和目标必须同种对象。规则级唯一性不能代替具体对象集合检查。重复输入源在 `validate_targets` 中跳过；此方法不检查所有规则是否命中，也不查询下游已存在表，未命中规则由任务层检查。`route` 本身不校验调用者输入。

## 并发与资源生命周期

构造后 API 只读，无后台任务或外部资源。路由需为小写键分配字符串，返回拥有的目标字符串；目标唯一性校验额外持有与对象数成比例的两个集合。

## 扩展指南

增加规则种类时同时维护解析、规范表达、唯一性和优先级；覆盖表规则覆盖库规则、非链式路由、未改名对象冲突、重复源和规则顺序稳定性。不要让指纹脱离实际路由语义。
